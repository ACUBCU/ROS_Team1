**08.11**
* 웹 대시보드 완성도 다지기: 마커 id 드롭다운을 하드코딩(0, 1) 대신 천장 카메라가 실제로 본 마커 id로 자동 채우도록 변경
* `run_command()`가 실패 이유(자리 미등록, 마커 못 찾음, 이미 그 자리, 도착 자리 점유 등)를 예외로 반환하도록 바꿔서, 이동 실패 시 웹 화면에 실패 원인이 그대로 표시되게 함 (전에는 서버 로그에만 남고 화면엔 "이동 중..."만 뜨고 끝났음)
* 천장 카메라 화면 클릭으로 박스 이동 기능 추가: 박스가 있는 자리 클릭 → 도착 자리 클릭하면 COMMAND가 그대로 실행됨 (드롭다운 선택 없이도 가능). 클릭 좌표는 자리 표시(십자가)가 그려지는 픽셀 좌표와 직접 비교해 가장 가까운 자리로 스냅함
* `/move` 실전 테스트 중 실제로 박스가 목표에서 60cm 벗어나 날아가는 현상 재현 → Gazebo 내부 좌표(물리엔진 진짜 값)를 직접 찍어가며 원인 추적. 결론: 코드 로직 문제가 아니라 (1) 예전에 안 죽인 좀비 프로세스, (2) 과도한 동시 요청으로 Gazebo 자체가 조용히 크래시(WSL GPU 드라이버 이슈)한 상태에서 명령을 보낸 것이 원인. Gazebo/웹서버를 깨끗하게 새로 켠 상태에서 재검증하니 목표에서 3cm 오차로 정상 착지함
* 그래도 만약을 대비해 그리퍼로 집은 직후 안정화 시간(`GRASP_SETTLE_SEC`)을 추가로 늘려서, 물리엔진이 접촉을 완전히 가라앉힌 뒤에 움직이기 시작하도록 방어적으로 보강
* `/move`가 60초 안에 안 끝나면 실제로는 성공했는데도 웹 화면엔 "실패"로 뜨는 버그 발견·수정 (실측 이동 시간 78~81초로 기존 60초 타임아웃보다 김 → 180초로 늘림)
* `RUN_GUIDE.md`에 "Gazebo가 죽었을 때 증상과 확인 방법(`ros2 topic hz /joint_states`)" 트러블슈팅 항목 추가
* 천장 카메라 클릭으로 박스 선택 방식을 "가까운 자리"가 아니라 "지금 실제 보이는 마커 중심"으로 바꿈(`nearest_marker_for_pixel`, `/pixel_to_marker`) - 박스가 자리에서 벗어나 있어도 눈에 보이는 대로 클릭 가능
* MoveIt 기반 정밀 집기 복구·재구현(`moveit_pick_place.py`, `web_control_moveit.py`, `launch/box_sort_moveit.launch.py`): 미리 가르친 자리가 아니라 카메라가 실시간으로 본 마커 좌표로 팔을 뻗음. 3가지 실제 버그를 진단·수정:
  1. pose 기반 IK가 방금 등록한 박스 충돌 모델과 겹쳐 항상 실패 → FK 그리드 탐색(`search_grasp_pose`)으로 교체
  2. 그리퍼 열기가 MoveIt 시작상태 범위 검사에서 부동소수점 오차로 거부됨 → 그리퍼는 MoveIt 계획 없이 컨트롤러에 직접 명령
  3. 집기→옮기기를 안전 높이 경유 없이 한 번에 이동시켜 박스가 끌려감 → box_sort_project.py의 3단계(들어올리기-회전-내려놓기) 패턴 재사용
  세 가지 다 고친 뒤 전체 시퀀스(계획→충돌회피→안전이동→그리퍼)는 에러 없이 끝까지 도는 것을 확인했으나, **실제 그립 성공률은 천장 카메라의 좌표 오차(~6cm, 보정 안 됨)에 막혀있음** - `HELP_NEEDED.md`에 정리
