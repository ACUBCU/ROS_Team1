## 1. 픽앤플레이스가 사실 하나도 검증이 안 되어 있었음을 발견

세션 시작 시점 상태: `box_sort_project.py`에 자리 8개(24개로 문서화됨)가 이미 채워져 있었고, "실제로 동작 확인함"이라고 이전 세션 기록에 적혀 있었음. 그런데 직접 박스의 실제 월드 좌표(`gz topic -e -t /world/<world>/pose/info`)를 이동 전/후로 비교해보니, 로그상 "성공"이라고 뜬 동작들이 실제로는 박스를 전혀 옮기지 못했거나 물리엔진이 박스를 멀리 튕겨내고 있었음이 드러남.

**교훈**: `FollowJointTrajectory`/`GripperCommand` 액션이 SUCCEEDED를 반환하는 것은 "박스가 실제로 옮겨졌다"는 증거가 전혀 아니다. 반드시 물체의 실제 좌표를 확인해야 한다.

## 2. 자리 2개로 축소 후, 실제 그립 버그 4가지를 순서대로 발견하고 해결

로그만 보고 판단하지 않고 매번 박스 좌표를 확인하는 방식으로 좁혀서 디버깅함.

1. **그리퍼 컨트롤러의 `allow_stalling` 기본값이 `false`**: 손가락이 물체에 막혀서 목표까지 못 닫으면 "실패"로 처리되던 것을 발견. `open_manipulator_ws`(git 저장소 밖)의 `hardware_controller_manager.yaml`에서 `gripper_controller`에 `allow_stalling: true`를 추가해서 "막히면 = 잡은 것"으로 정상화. (`stall_timeout`을 기본값 1.0초보다 짧게 줬다가 오작동한 적이 있어 기본값 유지.)
2. **박스를 쥔 채로 바로 회전하면 바닥 마찰 때문에 빠짐**: 8도만 돌려도 즉시 빠지는 것을 실측으로 확인. "들어올리기 → 회전 → 내려놓기" 3단계로 나눔.
3. **처음 접근할 때도 낮게 스쳐서 박스를 미리 건드리는 문제**: 관절-공간 궤적 보간이 중간에 목표보다 낮게 처지면서 박스에 닿았고, 그 상태에서 그리퍼를 닫으면 물리엔진이 겹친 충돌을 한 프레임에 풀어내며 박스가 36cm 이상 튕겨나감. 집기 전에도 "들어올린 높이"를 거쳐서 접근하도록 수정.
4. **시스템 부하가 높을 때 액션이 실제로는 성공했는데 결과 콜백이 늦게 와서 타임아웃으로 오판**: `MOVE_TIMEOUT_SEC`을 8초 → 15초로 늘림.

이 4가지를 고친 뒤 `run_command()`로 1번 자리 ↔ 2번 자리 왕복을 박스 좌표 확인까지 포함해서 2번 연속 성공시킴.

## 3. 그리퍼-박스 접촉이 시각적으로 "뚫고 들어가 보이는" 문제 확인 및 개선

사용자가 Gazebo 화면을 직접 보고 "그리퍼가 박스를 물리적으로 뚫고 들어가는 것 같다"고 지적. 박스 충돌(collision) 표면에 `kp`(강성)/`kd`(감쇠) 파라미터가 없어서 물리엔진 기본값(무른 편)을 쓰고 있었음을 확인하고, `aruco_cube/model.sdf`에 `kp=1e8, kd=1`을 추가해서 접촉이 더 단단해지도록 개선.

## 4. 아루코 박스 모델을 프로젝트 안으로 복사

`aruco_cube` 모델이 원래 `tf2_basic` 패키지 것이었는데, 사용자 요청으로 `이서현_project/models/aruco_cube/`에 복사해서 이 프로젝트 안에서 자체적으로 관리하도록 함. `GZ_SIM_RESOURCE_PATH`에서 `redball_sort_project` 경로를 `tf2_basic`보다 먼저 등록해서 우리 사본이 먼저 찾아지게 함(`tf2_basic` 원본은 다른 수업 예제를 위해 그대로 둠).

## 5. 오버헤드(천장 고정) 카메라 추가

손목 카메라만으로는 "박스를 찾는" 용도로 쓰기 어렵다는 판단 하에, 작업공간 전체를 위에서 내려다보는 두 번째 카메라를 추가함.

- 처음엔 로봇 URDF에 fixed joint로 손목 카메라와 같은 방식으로 넣었는데, 화면이 갱신 안 되는 것처럼 보이는 문제가 있어서 "정적 카메라 렌더링 버그"로 오판했었음 — 나중에 팔을 크게 움직여보고서야 실제로는 정상 작동 중이었고 단지 로봇 기본 자세가 위에서 보면 그렇게 구부러져 보이는 것뿐이었음을 확인(오해였음).
- 그래도 환경 고정 센서는 로봇 URDF보다 world 파일에 넣는 게 더 적절하다고 판단해서, `empty_world.sdf`에 독립된 `<static>true</static>` 모델로 최종 구현함.

## 6. 박스 2개 + 자리 4개로 확장, 천장 카메라로 "자리 점유" 판단 기능 추가

- 두 번째 아루코 박스(`aruco_cube_2`, 마커 id=1) 모델 생성 (마커 이미지도 `cv2.aruco`로 새로 생성).
- 자리를 2개 → 4개로 확장.
- 천장 카메라가 마커를 인식해서 어느 자리에 있는지 계산(`_nearest_slot`)하고, 프레임 하나 놓치는 것에 흔들리지 않도록 디바운스 로직 추가(`OCCUPANCY_MISS_LIMIT`).
- COMMAND 입력 방식을 "출발자리 도착자리"에서 "마커id 도착자리"로 변경 — 천장 카메라가 출발 자리를 스스로 찾음(`find_slot_of_marker`).
- 도착 자리가 이미 점유되어 있으면 이동을 거부하도록 함.

### 6-1. 이 과정에서 추가로 발견하고 고친 문제들

- **천장 카메라 화면비 문제**: 640x480 화면비 때문에 세로 시야각이 가로보다 좁아서 1번 자리가 화면 가장자리에 걸려 인식이 잘 안 됨 → 시야각을 60도 → 80도로 넓힘.
- **시야각을 넓히니 마커가 너무 작게(약 20px) 나와서 이번엔 인식률이 떨어짐** → 해상도를 640x480 → 1280x960으로 2배 올려서 해결(약 40px로 커짐).
- **로봇의 기본(홈, 관절 전부 0) 자세가 우연히 1번 자리 방향(0도)과 일치**해서, 로봇이 쉬고 있을 때 팔이 항상 1번 자리 박스를 가려서 천장 카메라가 못 보는 문제 발견 → 자리 배치를 0/90/180/270도에서 45/135/-135/-45도로 45도씩 어긋나게 옮겨서 해결.
- **자리가 늘면서(최대 180도 회전) 회전 속도가 기존 고정 시간 설정 때문에 오히려 빨라져서 박스를 놓치고 튕겨나가는 문제** 재발 → 이동 시간을 목표까지의 거리에 비례하게 계산하도록 변경(`ANGULAR_SPEED_LIMIT_RAD_S`).
- **속도를 늦춰도 여전히 박스를 살짝 놓치는 문제**: 팔은 정확히 목표 자리에 도착했는데 박스만 회전 초반에 원래 위치 근처에 남아있는 조용한 실패였음. 원인은 `gz_ros2_control`의 기본 `position_proportional_gain`(0.1)이 회전 중 버틸 만큼 그리퍼 힘이 세지 않았던 것 — 그리퍼 관절에 `position_proportional_gain=20.0`을 설정해서 해결. 이후 목표 지점 2cm 이내로 정확히 도착하는 것을 확인함.
- **박스가 넘어지거나 눕는 경우를 대비**해서, 원래 윗면에만 있던 아루코 마커를 박스 6면 전부에 붙임(양쪽 박스 모델 모두).

## 7. 최종 검증

`run_command()`를 실제 프로덕션 코드로 직접 호출하는 테스트 스크립트로, 박스 좌표까지 확인하며 다음을 검증함:
- 점유된 자리로 이동 시도 → 정상적으로 거부됨
- 빈 자리로 이동 → 정상적으로 이동, 목표 지점 2cm 이내 도착
- 반대 방향 이동도 정상 동작

## 8. 웹 페이지로 로봇 조작 (`web_control.py`)

터미널 키보드 조작 대신 브라우저에서 버튼으로 조작할 수 있게 새 프로그램(`redball_sort_project web_control`)을 추가함. `BoxSortProject` 클래스를 그대로 재사용하고, "로봇과 통신하는 스레드"와 "웹 요청을 받는 Flask 스레드"를 분리해서(큐로 명령 전달) 서로 안 막히게 구현.

- **TEACH(수동 조작)**: joint1~4 +/- 버튼, 그리퍼 열기/닫기, 자리 커서 이동, 자리 저장 — 키보드 `q/a/w/s/e/d/r/f/z/x/n/b/g`와 동일하게 동작.
- **COMMAND(박스 이동)**: 마커id + 도착 자리를 골라서 이동.
- **카메라 실시간 화면**: 천장/손목 카메라 화면을 MJPEG 스트리밍으로 웹에서 바로 볼 수 있음. `app.run(threaded=True)`를 안 켰으면 스트리밍 연결 하나가 서버 전체를 막아버려서, 반드시 켜야 함을 확인.
- `/status`, `/jog`, `/move`, `/video/overhead`, `/video/gripper` 각 엔드포인트를 curl로 직접 호출해서 실제로 로봇이 움직이고 영상이 스트리밍되는 것까지 확인함.

## 10. 웹 페이지에 자리 번호 상시 표시

사용자가 "1~4번 자리가 화면 어디인지 모르겠다"고 해서, 천장 카메라 화면에 **박스가 없어도** 1~4번 자리 위치를 십자가 표시 + 번호로 항상 그려주도록 추가함(`_slot_to_pixel`, `_draw_slot_labels`). 자리 번호 → world 좌표 → 화면 픽셀로 변환하는 계산은 기존 "마커 위치 → 자리 번호" 계산(`_nearest_slot`)의 역방향 공식을 그대로 씀. 빈 자리는 하늘색, 박스가 있는 자리는 주황색으로 구분. 실제 스트림에서 프레임을 뽑아 박스 위치와 자리 표시가 정확히 겹치는 것까지 확인함.

## 11. "회전이 최단거리로 안 가고 돌아간다"는 질문에 답변

원인은 버그가 아니라 `joint1`(허리 관절)이 URDF상 정확히 ±180도(`±pi`)까지만 도는 하드웨어 한계이기 때문. 자리끼리 거의 반대편에 있을 때(예: 135도 ↔ -135도)는 ±180도 경계를 넘어가는 "짧은 길"이 관절 한계 때문에 애초에 갈 수 없는 경로라, 0도 쪽을 통과하는 "먼 길"이 유일하게 가능한 경로임. 코드를 고치기보다 이 사실을 설명하는 것으로 마무리함(자리 배치를 바꾸면 최악의 경우가 달라질 수는 있지만, 4자리를 원 전체에 펼치는 이상 어떤 배치든 한 쌍은 항상 이런 먼 길을 가야 함).
